# 桌面端不再开出任何空白窗口，Penguin Go 授权在桌面端直接打开授权页

- **Date:** 2026-09-18
- **Type:** fix
- **Scope:** `desktop`, `web`

[English](2026-09-18-desktop-auth-bridge.md)

桌面壳的新窗口规则之外曾有一个例外：Penguin Go 授权开始时，Web App 先开一个隐藏的 `about:blank`
窗口，待 server 返回授权地址后再把它导航过去。文件面板中预览的 HTML 文件也能要到同一个窗口——其 iframe
允许弹窗，而壳分不清请求来自哪一帧；空白窗口继承打开者的源，预览页脚本因此可以在不可见处操控它，只要
脚本愿意就一直留着。现在壳拒绝一切空白窗口，Web App 在壳内也不再请求这样的窗口。

## 桌面端

- 对 `about:blank` 的请求——不带地址的 `window.open()`——与其他非 web 协议一样被拒绝，主窗口与它打开的
  每个窗口一律如此。主窗口不再有自己的新窗口例外。
- 其余规则保持不变：Workspace 预览的交接路由、预览主机上的页面与拆出的终端获得应用内窗口；指向其他
  地方的 `http(s)` 与 `mailto` 链接交给系统浏览器；本实例的其余地址一律拒绝并记日志。

## Web App

- 在桌面壳自己的窗口里，Penguin Go 的「授权」点击不再先开空白标签页。server 返回授权地址后，页面直接
  打开它，由壳转交系统浏览器——Electron 没有弹窗拦截器，浏览器里必须在点击内开出的那个标签页在这里
  并不需要。
- 在浏览器里——包括登录到桌面模式 server 的浏览器——流程不变：点击内先开一个空白标签页，地址返回后
  再导航到授权页。
