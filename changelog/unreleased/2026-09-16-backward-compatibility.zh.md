# 向后兼容

- **Date:** 2026-09-16
- **Type:** process
- **Scope:** `server`, `core`, `model-catalog`
- **Breaking:** yes — 此前同步过预置的 Project 在执行「同步预置」之前，仍保留预置时写入的折后价，促销结束后这些行也继续按旧折扣计费

[English](2026-09-16-backward-compatibility.md)

[请求成本在请求完成时定格](2026-09-16-usage-cost-at-record-time.zh.md)涉及三处已经在磁盘上的数据：`web.db` 里只有 Token、没有成本的用量记录；各 Project 的 `.project_config.toml` 中，早先版本给促销行写入的折后价；以及 `token_usage` 事件不带单价的 Trace。

## 升级前写入的用量记录

采用：**启动时一次性补算。** 迁移 9 新增 `usage_records.cost` 与 `usage_records.cost_settled`，已有记录一律标为未定格。启动时 `UsageService.settleUnsettledCosts` 为每条未定格记录补算一次成本：价格取该记录所属 Project 此刻存的价格，规则沿用早先版本的计费方式——存的价格原样计费，仅当该行仍是目录高峰价、且记录自身的时间戳落在空闲时段时按空闲档计。升级前后成本中心显示的数字不变，此后也不再变动。热更新回滚到旧版本期间写入的记录，同样由这一步补算。

用户无需任何操作。

**移除：** `settleUnsettledCosts`、其 `legacyRates` 规则以及 `Startup` 中调用它的一行，在本改动所在版本之后的第二个版本做发布准备时移除。此后若有 `web.db` 一次跨过这两个版本升级，其旧记录保持未计价：仍计入 Token 与请求数，不计入成本。迁移 9 与其他迁移一样保留。

## Project 中已有的折后价

采用：**不做迁移，由用户执行一次同步预置。** 早先版本把促销行的折后价写进了 Project。这个数已不是目录牌价，因此该行按「用户自填的价格」处理：

- 按存的价格计费，促销结束后也一样；
- 模型页不显示折扣徽标；
- 「模型库」入口的同步角标把它计入可同步的预置模型。

执行一次**同步预置**即写回牌价，此后该行跟随目录的促销，无需再同步。用户手工填过价的行不受影响。没有需要移除的兼容代码。

## 不带单价的 Trace

`token_usage` 新增可选字段 `pricing`。此前写入的 Trace 没有该字段，需要这类事件成本的消费方按同一规则自行取价。没有读取方依赖这个字段一定存在，因此无需迁移，也没有需要移除的代码。

## 兼容性

用量记录与 Trace 无需任何操作。对于在此改动之前同步过预置的每个 Project，请在其模型页执行一次**同步预置**；在此之前，其促销行按存下的折后价计费。
